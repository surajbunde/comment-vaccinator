# Design Spec — v1.4.0 "Spam Filters" Pack

**Date:** 2026-10-20
**Status:** Approved
**Supersedes:** nothing (additive to v1.3.5)

---

## 1. Goal

Extend Comment Vaccinator with more filtering power. v1.4.0 ships five new
stateless text-heuristic filters plus a per-reason stats breakdown so users can
see *which* filter is doing the work and tune it.

v1.5.0 (out of scope here) will add the three stateful/contextual filters:
duplicate detection, block-by-author, comment age.

## 2. User-facing scope (v1.4.0)

| Filter | What it hides | Options |
|---|---|---|
| Links | Comments containing a URL (http/https, `www.`, or a bare domain) | Allowed-domains allow-list |
| Contacts | Comments containing an email, a phone number, or a Telegram/WhatsApp handle | — |
| All-caps | Comments written entirely in capital letters | Minimum letter count (default 15) |
| Spam punctuation | Comments with `!!!`, `???`, `....`, repeated letters, doubled words, spaced-out text | — |
| Extra date locales | Date mentions in Spanish, French, German, Portuguese, Russian | — |

**All five ship OFF by default.** Existing users see zero behaviour change on
upgrade. Each is opted into individually, matching the precedent set by the
custom-patterns toggle.

**The keyword whitelist still overrides everything** — a whitelisted comment is
never hidden by any of the new filters.

## 3. Architecture

### 3.1 Module layout

New pure modules under `src/matchers/`, with **no browser API dependencies** so
they stay Node-importable and unit-testable, exactly like the existing matchers:

```
src/matchers/
  links.js        → extractLinks(text), matchesLinks(text, allowedDomains)
  contacts.js     → matchesContacts(text)
  caps.js         → matchesCaps(text, { minLength })
  punctuation.js  → matchesSpamPunctuation(text)
  dateLocales.js  → LOCALE_DATE_PATTERNS, matchesLocaleDate(text)
  spamFilters.js  → runSpamFilters(text, spamSettings)   ← composer
```

`spamFilters.js` is the single entry point the pipeline calls. It runs the five
matchers in a fixed order and returns the first hit.

### 3.2 Storage

One new key, `cv_spamFilters`, holding a JSON string:

```json
{
  "linksEnabled": false,
  "linksAllowedDomains": "",
  "contactsEnabled": false,
  "capsEnabled": false,
  "capsMinLength": 15,
  "punctuationEnabled": false,
  "localesEnabled": false
}
```

A nested blob (rather than 10 flat keys) keeps the key count sane and matches
the existing precedent of JSON-string keys (`cv_customPatterns`,
`cv_perVideoDisabled`). Parse failure falls back to defaults — same defensive
pattern already used in `buildFromRaw`.

### 3.3 Pipeline

`FilterResult` gains a stable `reasonCode` alongside the human-readable
`reason`:

```js
{ hide: boolean, reasonCode: string, reason: string, patternName: string }
```

Reason codes: `whitelist`, `emoji-only`, `keyword`, `links`, `contacts`,
`caps`, `punctuation`, `locale-date`, `date`, `custom-pattern`, `word-count`.

New evaluation order:

1. **Whitelist** — always first, always wins (never hides)
2. Emoji-only
3. Keyword blacklist
4. **Spam pack** (contacts → links → caps → punctuation → locale-date)
5. Date (existing EN + Devanagari)
6. Custom patterns
7. Word count

The spam pack sits after the keyword blacklist so explicit user keywords win,
and before the date filter so the most specific reason is reported first. The
whitelist staying first means no new filter can hide a protected comment.

Within the pack, **contacts run before links** so that a comment carrying an
email address is reported as `contacts` rather than as `links` (an email
contains a domain, so the links matcher would otherwise claim it and the
breakdown would misattribute it).

When every spam sub-filter is disabled, `runSpamFilters` returns `null`
immediately — no regex work at all.

### 3.4 Stats breakdown

The content script already stamps `data-cv-reason` on hidden threads. v1.4.0 adds
`data-cv-reason-code` and returns a `byReason` map from the stats message. The
popup renders a "Hidden by filter" breakdown, sorted by count descending, only
for reasons with a non-zero count.

This is the payoff for adding five filters at once: without it, users cannot
tell which filter is misfiring.

## 4. Matching rules

### 4.1 Links

- Detects `https?://…`, `www.…`, and bare domains built from a curated TLD list
  (`com net org io co in link xyz me tv gg site online shop store app dev blog
  news fun space club icu buzz ly tk ml ga cf gq work live life world today top
  vip fyi ltd site sh`).
- The allow-list is comma-separated. A link is permitted when its hostname
  equals an allowed domain or ends with `"." + allowedDomain`, so allowing
  `youtube.com` also permits `www.youtube.com` and `m.youtube.com`.
- Returns the first *disallowed* link's hostname.

### 4.2 Contacts

Deliberately conservative, because phone detection is the easiest place to
falsely hide real comments.

- **Email** — `local@domain.tld`.
- **Phone** — only these shapes:
  - international with `+` prefix (`+91 98765 43210`)
  - leading-zero national form (`098765 43210`)
  - 3-3-4 and 5-5 grouped forms (`987 654 3210`, `98765 43210`)
  - 7–15 digits joined by `.`, `-`, or space
  - A bare digit run with no separators never matches, so `20240101`, `100`, and
    `12345` are safe.
  - `12/04/24` is safe — `/` is not a permitted separator.
- **Telegram / WhatsApp** — `t.me/…`, `telegram.me/…`, `wa.me/…`, plus
  `telegram`/`tg`/`whatsapp` followed by a handle or number.

### 4.3 All-caps

Word-based, not character-based, so a single acronym does not condemn a
sentence.

- Words are split on whitespace and stripped of surrounding punctuation.
- Words shorter than 2 letters are ignored.
- A comment matches when: total letter count ≥ `minLength` (default 15), at
  least 3 words are entirely uppercase, and uppercase words make up ≥ 80% of
  the counted words.

### 4.4 Spam punctuation

Triggers:

- 3 or more `!`, 3 or more `?`, or 4 or more `.` (a lone `...` stays allowed).
- 3 or more of the same non-space, non-punctuation character in a row.
- A word of 4+ characters repeated back-to-back (`same same`, `spam spam`),
  excluding a stop-list of legitimate doubled function words.
- 3 or more single letters separated by spaces (`c h e e k`).

### 4.5 Extra date locales

Separate module from the existing `datePatterns.js` so the new locales can be
opt-in without changing the behaviour of the existing always-on date filter.

Relative phrases per locale, plus month names that must be adjacent to a number
(this avoids matching a bare month word such as the German name "Mai"):

- **ES** — `hace 3 días`, `hace un mes`, `ayer`, `hoy`, `mañana`, `3 días atrás`
- **FR** — `il y a 2 ans`, `hier`, `aujourd'hui`, `demain`, `il y a 3 semaines`
- **DE** — `vor 3 Tagen`, `gestern`, `heute`, `morgen`, `vor einem Jahr`
- **PT** — `há 2 dias`, `ontem`, `hoje`, `amanhã`, `há uma semana`
- **RU** — `3 дня назад`, `2 недели назад`, `сегодня`, `вчера`, `завтра`

## 5. Error handling

- All new patterns are static literals — no user-supplied regex, so no ReDoS
  surface and no need for pattern timeouts.
- `cv_spamFilters` that fails to parse, or that contains wrong types, falls
  back to defaults field by field.
- The domain allow-list is compared with plain string operations, never
  compiled into a regex.
- If a matcher throws, `runSpamFilters` catches and returns `null` — a broken
  spam filter degrades to "no opinion" rather than breaking the whole
  pipeline.

## 6. Testing

- One `node:test` file per new matcher, covering positive cases, the documented
  false-positive guards (dates, `10/10`, bare digits), and edge cases
  (empty string, emoji-only, very long comments).
- Pipeline tests for the new ordering: whitelist still beats the spam pack;
  the spam pack reports before the date filter; a disabled spam filter changes
  nothing.
- Settings tests for `cv_spamFilters` parsing, defaults, and malformed input.
- Target: 138 existing tests stay green, ~70 new tests added.
